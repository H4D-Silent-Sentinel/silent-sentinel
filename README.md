# Silent Sentinel

Passive acoustic sensor network that keeps tracking small drones after they fly behind buildings and drop out of radar, camera and RF coverage.

Six listening nodes (ESP32-S3 + 4× ICS-43434 mics + RFM95W LoRa) detect the rotor tone comb and send small reports over LoRa to a base laptop, which estimates position from loudness and tracks the drone with a Kalman filter. All equipment is receive-only on drone frequencies.

## Layout

| Path | What |
|---|---|
| `firmware/node/` | Listening node: dual-I2S capture, comb detector, LoRa reports. Pins in `config.h`. |
| `firmware/base_rx/` | Base receiver: forwards LoRa packets to the laptop over USB serial. |
| `cuas/detector.py` | Reference detector (numpy). The firmware mirrors it; tune here first. |
| `cuas/packet.py` | 24-byte LoRa packet format (matches `firmware/node/packet.h`). |
| `cuas/sim/` | Synthetic drone / noise / wind / generator audio. |
| `cuas/base.py`, `localize.py`, `tracker.py` | Base station: loudness position fixes, multi-sensor Kalman tracker. |
| `cuas/radar.py`, `firmware/radar_bridge/`, `docs/radar.md` | Bench radar (RD-03D) for the radar-to-acoustic handoff demo. |
| `cuas/visual.py`, `docs/jetson-interface.md` | Interface to the Jetson Visual-Tracker (UDP JSON both ways). |
| `cuas/cot.py`, `cuas/mapserver.py` | Outputs: Cursor-on-Target to TAK, live local map. |
| `cuas/sim/scenario.py` | Network simulator driving the real base code. |
| `sites/` | Site files: node and camera positions. |
| `docs/wiring.md` | Node schematic (PNG/PDF/HTML, generated by `docs/make_wiring.py`). |
| `docs/breadboard.html` | Hole-by-hole breadboard layout for the first node (generated by `docs/make_breadboard.py`). |

## Build Firmware

```sh
arduino-cli core install esp32:esp32
arduino-cli lib install LoRa
FQBN="esp32:esp32:esp32s3:PSRAM=opi,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,USBMode=hwcdc,CDCOnBoot=cdc"
arduino-cli compile --fqbn $FQBN firmware/node
arduino-cli upload  --fqbn $FQBN -p /dev/cu.usbmodemXXXX firmware/node
```

Either USB-C port works; the console prints on both. First flash over the native **USB** port of a board still running the factory demo: hold BOOT, tap RST, release BOOT. After that, uploads reset it automatically. Serial console at 115200: `id <n>`, `debug 0|1`, `info`, `tx`.

A node also prints every packet it sends as a `PKT` line, so `python -m cuas run --serial <node port> --map` works with a node plugged straight into the laptop (no base receiver needed).

## Python

```sh
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
```

## Run Base

```sh
.venv/bin/python -m cuas sim --site sites/example_intersection.json --map      # simulated drone, map at http://127.0.0.1:8080
.venv/bin/python -m cuas ports                                                 # find the base receiver
.venv/bin/python -m cuas run --site sites/example_intersection.json --serial /dev/cu.usbserial-XXXX --map --cot
.venv/bin/python -m cuas sim --site sites/radar_handoff.json --map                # radar loses the drone, acoustic keeps the track
.venv/bin/python -m cuas listen --site sites/demo_bench_radar.json --radar /dev/cu.usbmodemXXXX --map  # bench demo: laptop mic + radar
.venv/bin/python -m cuas detect recording.wav -v                               # run the node detector on a recording
.venv/bin/python -m pytest                                                     # tests (also checks firmware detector == Python)
```
